# DAMO 안심 가로등

AI가 도로를 보고 필요한 곳만 가로등을 밝게 켜고, 어린이보호구역 위험을 운전자에게 알리고, 고장 날 가로등을 미리 찾아 주는 관제 서비스의 시연판입니다. 노트북이나 휴대폰 하나로 돌아갑니다.

- 배포: https://damo-ai.vercel.app
- 시장 조사와 사업 계획: [docs/market-and-plan.md](docs/market-and-plan.md)

## 화면 구성

휴대폰에서는 아래 탭, 넓은 화면에서는 왼쪽 메뉴로 이동합니다. 주소 끝에 `#school`처럼 탭 이름을 붙이면 그 화면이 바로 열립니다.

| 탭 | 하는 일 | 쓰는 AI·기술 | 데이터 | 코드 |
|---|---|---|---|---|
| 관제 (`#live`) | 사람·차를 인식·추적하고, 가는 방향을 예측해 앞 가로등을 미리 켬. 통행량을 예측해 한산할 때 밝기를 낮춤 | 물체 인식 + 다중 객체 추적, 등속 운동 예측, Holt 지수평활 | **실측** (카메라) | `lib/detectors.ts`, `lib/tracker.ts`, `lib/predictive.ts`, `lib/forecast.ts` |
| 스쿨존 (`#school`) | 과속, 보행자 충돌 위험, 불법 주정차, 보행자 횡단을 찾아 전광판 문구·음성으로 알리고 경고 후 감속률을 집계 | 추적·이동 예측 위 규칙, 시간대별 제한속도 | 카메라 **실측** + 지도 시뮬레이션 | `lib/schoolzone.ts`, `components/SchoolZonePanel.tsx` |
| 시설 점검 (`#facility`) | 전압 불안정·과열·LED 드라이버 노후를 고장 전에 찾음 | 규칙, 로버스트 z 이상 탐지, Random Forest | 가상 센서 (MQTT로 실제 장비 연결 가능) | `lib/sim.ts`, `lib/ml.ts` |
| 에너지 (`#energy`) | 아낀 전기와 줄인 탄소, 내일 태양광 충전 예보 | Gradient Boosting 발전량 예측 | 기상 예보 | `lib/solar.ts`, `components/SolarPanel.tsx` |
| 보고서 (`#report`) | 오늘 현황(스쿨존 포함)을 담당자용 보고서로 작성 | 무료 LLM (로컬 Ollama 또는 Gemini) | 위 데이터 | `app/api/report/route.ts` |
| 태양광 설치 검토 (`/siting`) | 주소로 지목·용도지역을 확인하고 지자체 조례를 적용해 설치 가능성 판정 | 규칙 + LLM 조문 해석 | 공공 API | 아래 "태양광 입지 분석" |

### 현장 카메라 창

카메라는 영상통화처럼 화면 위에 떠 있는 창이고, 어느 탭에서든 계속 돌아갑니다(`components/CameraDock.tsx`).

- **창 모드:** 끌어서 옮기면 가까운 모서리에 붙습니다. 영상을 톡 누르면 전체 화면으로 바뀝니다.
- **전체 화면:** 카메라를 크게 보여 주고, 구석의 작은 지도를 누르면 관제 화면으로 돌아갑니다. 앞·뒤 카메라 전환과 끄기 버튼이 여기 있습니다.
- **최소화:** 작은 동그라미만 남기고, 분석은 계속 돕니다.
- **휴대폰:** 권한 창이 갑자기 뜨지 않게 **카메라 켜기** 버튼으로 시작하고, 도로를 비추도록 뒷면 카메라를 씁니다. 카메라는 https에서만 켜지므로 배포 주소로 접속하세요.
- **노트북:** 바로 켜지고, 앞면 카메라에서는 손동작으로 카메라 구간을 옮길 수 있습니다.
- **개인정보 가림:** 기본으로 켜져 있어 사람 머리와 차량 번호판 부분을 모자이크합니다. 스쿨존 → 현장 설정에서 끌 수 있습니다.

### 스쿨존 판단 기준

| 사건 | 기준 | 전광판 |
|---|---|---|
| 과속 | 시간대 제한속도 초과. 등교 7:30~10시·하교 13~18시 30km/h, 야간 탄력 운영 시 50km/h | 속도 + "속도를 줄이세요" |
| 충돌 위험 | 보행자가 있는데 1.5초 뒤 차량 예상 위치가 보행자에게 닿음 | "멈추세요" (깜빡임) |
| 불법 주정차 | 구역 안에서 설정 시간(기본 10초) 넘게 멈춘 차량 | "주정차 금지" |
| 보행자 횡단 | 카메라에 새 보행자가 잡힘 | "어린이 보호 · 서행" |

카메라 속도는 화면 속 이동 거리를 "화면이 비추는 도로 폭" 설정으로 환산한 추정값입니다. 경고·통계용이고 단속 근거로는 쓸 수 없습니다. 지도의 가상 차량은 4대 중 1대꼴로 과속하고, 경고를 보면 70% 확률로 감속하도록 시뮬레이션합니다.

### 인식 엔진 자동 선택

브라우저 환경에 따라 되는 엔진을 자동으로 고릅니다. 사용 중인 엔진은 카메라 패널 오른쪽 위에 표시됩니다.

1. **MediaPipe GPU**: 가장 빠릅니다. WebGL2가 필요합니다.
2. **MediaPipe CPU**: GPU 추론만 실패할 때 씁니다.
3. **TF.js COCO-SSD (WASM)**: WebGL이 막힌 브라우저에서도 CPU만으로 동작합니다. `StartGraph failed: kGpuService ... emscripten_webgl_create_context()` 에러가 나던 환경에서는 이 엔진이 쓰입니다.

CPU 엔진으로 돌고 있다면 크롬 설정의 "그래픽 가속 사용"(chrome://settings/system)을 켜 보세요. VS Code 안의 미리보기 브라우저보다 크롬이나 엣지에서 여는 것을 권장합니다.

영상 인식 AI는 모두 브라우저 안에서 돌아가 카메라 영상이 밖으로 나가지 않습니다. 보고서 AI만 로컬 Ollama(노트북) 또는 Gemini 무료 API(배포 서버)를 씁니다. 유료 API 키는 필요 없습니다.

## 실행

```bash
# 1. 로컬 LLM 서버 (터미널 하나를 계속 열어 둠)
ollama serve

# 2. 모델 받기 (최초 1회, 약 3GB)
ollama pull gemma3:4b

# 3. 앱 실행 (다른 터미널)
npm install
npm run dev
```

http://localhost:3100 을 엽니다. 노트북은 카메라가 바로 켜지고, 휴대폰은 카메라 창의 **카메라 켜기**를 누릅니다.

### 시연 순서

1. **관제 탭:** 카메라 앞을 좌우로 천천히 걸어 봅니다. 지도에서 가는 방향의 가로등이 미리 켜지고(주황 링), "움직임 예측"에 번호·방향·다음 가로등 도착 시간이 나옵니다.
2. **화면 밖으로 나가기:** 화면 밖으로 나가도 지도에 점선 원으로 추정 위치가 이어집니다.
3. **스쿨존 탭:** 카메라 앞에서 사람과 차(휴대폰 화면 속 자동차 사진도 됩니다)가 함께 잡히면 전광판이 "멈추세요"로 바뀝니다. 가만히 두면 지도의 가상 차량 과속 기록과 "경고 후 감속"이 쌓입니다.
4. **시설 점검 탭:** **고장 시연하기**를 누르고 AI가 몇 초 만에 찾아내는지 봅니다.
5. **보고서 탭:** **지금 상태로 보고서 만들기**를 누르면 LLM이 스쿨존 기록까지 담아 보고서를 씁니다.
6. **휴대폰:** 휴대폰으로 배포 주소를 열고 카메라 창을 끌어 옮기거나 전체 화면으로 바꿔 봅니다.

### 모델 바꾸기

더 좋은 한국어 문장이 필요하면 큰 모델을 쓰세요. 메모리 48GB 노트북이면 12B 모델도 충분히 돌아갑니다.

```bash
ollama pull gemma3:12b
OLLAMA_MODEL=gemma3:12b npm run dev
```

## 태양광 입지 분석 (/siting)

주소를 넣으면 그 필지의 지목·용도지역·토지이용계획 구역을 확인하고, 관할 지자체 조례의 발전시설 기준을 적용해 지상형 태양광을 설치할 수 있는지 1차로 판정합니다. 메인 화면 제목 아래 **태양광 입지 분석 →** 링크로 들어갑니다.

| 단계 | 하는 일 | 데이터·기술 | 코드 |
|---|---|---|---|
| 토지 조회 | 주소 → 필지(PNU) → 지목, 용도지역, 농업진흥구역·개발제한구역·보전산지 같은 구역 | 브이월드 오픈API (무료 키) | `lib/land.ts` |
| 조례 수집 | 관할 시·군·구의 도시·군계획 조례(자치구·제주시 등은 광역 조례 포함), 제목에 태양광이 든 조례 | 법제처 국가법령정보 공동활용 API (무료) | `lib/ordinance.ts` |
| 기준 추출 | 발전시설 조문에서 "도로에서 500미터" 같은 이격거리·경사도 기준을 뽑음. 풍력 전용 항과 호수 산정용 거리는 뺌 | 규칙 기반 파싱 | `lib/siting.ts`의 `extractSetbacks()` |
| 판정 | 지목·용도지역·구역은 전국 법령 기준, 이격거리는 입력한 부지 주변 거리와 비교. 가장 엄격한 항목이 종합 판정 | 규칙 | `lib/siting.ts`의 `assess()` |
| 검토 의견 | 조례 조문을 읽고 예외 조항, 인허가 절차, 현장 확인 사항을 정리 | 로컬 LLM (Ollama, 무료) | `app/api/siting/report/route.ts` |

판정은 규칙으로 정하고, LLM은 조문을 풀어 설명하는 역할만 맡습니다. 필요한 인허가 목록도 규칙으로 정해 넘기기 때문에 LLM이 절차를 지어내지 않습니다.

### 인증키

```bash
# .env.local
VWORLD_KEY=브이월드에서 발급받은 키            # https://www.vworld.kr → 오픈API → 인증키 발급
VWORLD_DOMAIN=http://localhost:3100           # 키 발급 때 등록한 서비스 URL
LAW_OC=법제처 OC                               # https://open.law.go.kr 가입 이메일의 @ 앞부분
```

- `VWORLD_KEY`가 없으면 **직접 입력** 모드로만 동작합니다. 토지이음(eum.go.kr)의 토지이용계획확인서를 보고 지목·용도지역·구역을 고르면, 조례 조회와 판정은 똑같이 돌아갑니다.
- `LAW_OC`가 없으면 법제처 예시 계정(`test`)을 씁니다. 언제든 막힐 수 있으니 꼭 발급받으세요.

### 확인 방법

```bash
npx tsx scripts/check-siting.ts   # 지자체 8곳의 조례 수집과 이격거리 추출 결과를 출력
```

### 한계

- 부지에서 도로·마을까지 거리는 자동으로 재지 않습니다. 화면에 직접 입력해야 이격 판정이 됩니다.
- 도로 종류(국도·지방도·군도)나 마을 규모(10호 이상·미만)에 따라 기준이 다르면 가장 엄격한 값과 비교합니다. 실제로는 더 느슨한 기준이 적용될 수 있습니다.
- 조례 별표(한글 파일)는 읽지 못합니다. 용도지역별 건축 제한이 별표에만 있으면 법제처 링크로 확인하세요.
- 사전 검토용입니다. 인허가 결과는 지자체 허가 부서가 정합니다.

## 고장 탐지 ML (④)

시뮬레이터로 정상·고장 데이터를 만들고, Python으로 학습해 브라우저에서 돌립니다.

```bash
npx tsx scripts/export-dataset.ts             # ml/data/train.csv, test.csv (37만·12만 행)
ml/.venv/bin/python ml/train_fault.py         # 학습·채점 → ml/results/fault.json, public/models/fault-*.json
npx tsx scripts/check-parity.ts               # 브라우저 계산이 scikit-learn과 같은지 확인
```

Python 환경이 없다면 `python3 -m venv ml/.venv && ml/.venv/bin/pip install pandas scikit-learn`로 만드세요.

시험 데이터(학습에 안 쓴 8회 × 44대 × 6시간, 고장 58건) 채점 결과:

| 방법 | 학습 | 탐지율 | 첫 경보까지 (중앙값) | 오경보 (대·일) |
|---|---|---|---|---|
| 규칙 (사람이 정한 기준) | 없음 | 88% | 24분 | 0 |
| Isolation Forest | 정상 데이터만 | 24% | 40분 | 0.80 |
| 로버스트 z + 5분 연속 | 정상 데이터만 | 90% | 18분 | 0.05 |
| Random Forest + 3분 연속 | 정상 + 고장 라벨 | **98%** | **11분** | **0** |

Isolation Forest는 학습 범위를 벗어난 값(강한 고장)을 정상 데이터의 끝값과 같은 점수로 매기는 한계 때문에 이 데이터에서는 쓸 수 없었습니다. 화면의 "④ 고장 예측"에서 세 방법을 바꿔 가며 볼 수 있습니다.

주의: 이 모델은 시뮬레이터가 만든 고장 모양을 배웠습니다. 현장 고장 데이터로 다시 학습하기 전까지는 실제 성능이 아닙니다.

## 태양광 발전량 예측 (⑥)

```bash
ml/.venv/bin/python ml/train_solar.py         # 2022~2024 학습, 2025 시험 → public/models/solar-gbr.json
npx tsx scripts/check-solar.ts                # TS 계산·기상청 격자 변환 확인
```

- 입력은 기상청 단기예보에 있는 값만 씁니다: 하늘상태(SKY), 강수(PTY), 기온(TMP), 습도(REH), 맑은 하늘 일사량(날짜·시각으로 계산).
- 과거 발전량은 실측 기록이 없어서 Open-Meteo 과거 일사량 관측값에 패널 물리식(150W, 손실 20%, 온도 보정)을 적용해 만들었습니다.
- 설치 지점 기본값은 서울시청입니다. 바꾸려면 `SITE_LAT=35.18 SITE_LON=129.08 ml/.venv/bin/python ml/train_solar.py`로 다시 학습하세요.
- 기상청 예보를 쓰려면 [공공데이터포털](https://www.data.go.kr/data/15084084/openapi.do)에서 "기상청_단기예보 조회서비스" 활용 신청 후 `.env.local`에 `KMA_SERVICE_KEY=발급받은키`를 넣고 서버를 다시 시작하세요. 없으면 Open-Meteo 예보를 씁니다.

2025년 하루 발전량 예측 오차 (일평균 실제 463Wh):

| 방법 | 입력 | 오차 | 흐린 날 오차 |
|---|---|---|---|
| 내일도 오늘과 같다 | - | 136Wh (29%) | - |
| 맑은 하늘 × 하늘상태 비율 | 과거 예보 | 83Wh (18%) | 134Wh |
| Gradient Boosting | 과거 예보 | **64Wh (14%)** | **106Wh** |
| Gradient Boosting | 실제 날씨 (상한) | 44Wh (10%) | 48Wh |

배터리 위험 판단: 용량 1.5kWh, 밤 12시간 가정. 오늘 밤 사용 → 내일 충전 → 내일 밤 사용 뒤 20% 미만이면 위험으로 표시합니다.

## 실제 기기 연결 (⑦)

```
라즈베리파이 ──MQTT(1883)──▶ Mosquitto 브로커 ◀──WebSocket(9001)── 관제 화면
  sensor_agent.py : 전압·전류·온도 보냄, 밝기 명령 받음
  edge_camera.py  : 기기에서 인식, 결과(박스)만 보냄
```

노트북 한 대로 전체 경로 시험:

```bash
brew install mosquitto
mosquitto -c device/mosquitto.conf
python3.13 -m venv device/.venv && device/.venv/bin/pip install -r device/requirements.txt
device/.venv/bin/python device/sensor_agent.py --lamp L-05 --simulate --interval 1 --fault overheat --fault-after 30
device/.venv/bin/python device/edge_camera.py --camera cam-1 --source 0      # 노트북 웹캠
```

관제 화면의 "⑦ 실제 기기 연결"에서 **연결**을 누르면 L-05가 실제 값으로 바뀌고(지도에 파란 사각 테두리), 계산한 밝기가 명령으로 기기에 갑니다.

라즈베리파이에서는 `--simulate`를 빼고 `--broker <관제 PC 주소>`를 주면 됩니다. 배선: INA219(I2C 0x40)로 LED 드라이버 입력 전압·전류, DS18B20(1-Wire)으로 방열판 온도, GPIO18 PWM으로 디밍. 현장에서는 `--interval 60`으로 두세요(고장 모델이 1분 간격 데이터로 학습됨).

주의
- 브로커는 데모용으로 익명 접속을 허용합니다. 현장에서는 비밀번호와 TLS를 켜세요.
- 엣지 카메라 모델(SSD MobileNet v1, 2018)은 오래되어 몸 일부에 박스를 덧붙이는 경우가 있어 점수 기준을 0.6으로 높였습니다. PoC에서는 더 최신 모델로 바꾸는 것을 권장합니다.
- 실물 센서 코드(INA219, DS18B20, PWM)는 라즈베리파이 없이 작성했으며 아직 실기 시험 전입니다.
